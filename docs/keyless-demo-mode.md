### The chart, honestly

The keyless subset publishes no `/v2/cryptocurrency/ohlcv/historical` and no `/v3/cryptocurrency/quotes/historical`, so
there is no keyless series for a CMC asset id. The keyless chart therefore asks `/v1/k-line/candles` for the **WETH
contract on Ethereum** (`0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2`) and labels it as what it is: a DEX aggregate
across every pool on the chain, not the CoinMarketCap reference price of ETH. The chart's coverage sentence says so on
screen.

k-line rows are positional arrays `[open, high, low, close, volume, timestampSeconds, traders]`. Per the rules already
established for the keyed k-line source: the timestamp is a period **open** in seconds; the provider publishes **no
close time**, so `closedAt` is derived from the candle width the request pinned and is stated to be derived; a period
still in progress is dropped rather than drawn; a zero-volume completed period keeps its zero; only the eight named
candle widths are accepted; and `unit=usd` is pinned so `volumeUnit` is `USD` and `volumeKind` is `period`.

### Rules the code enforces

* **No key, ever.** `createResearchService` sets `key=''` when the mode is keyless, `server/index.mjs` does not even
  read `CMC_API_KEY` in that mode, `/api/status` reports `keyConfigured: false`, the request carries exactly one header
  (`Accept`), and the URL is asserted to start with the keyless base before the fetch. A test inspects the recorded
  request and fails if anything matching `CMC_PRO_API_KEY|apikey|api_key|authorization` appears anywhere in it; the
  packaging regression fails if the client's source mentions a key environment variable at all.
* **Labelled.** Every keyless answer — success or failure — carries `source: 'coinmarketcap_keyless'`, `mode: 'keyless'`
  and `retrievedAt`. A success additionally carries `provenance.fetchedAt` (equal to `retrievedAt`) and
  `provenance.observedAt`, the provider's own clock: the quote's `last_updated` for the standard routes, the newest
  candle open for k-line. A failure leaves `fetchedAt` null, because nothing was fetched.
* **Cached for 30 seconds, per route.** Key is capability plus canonical parameters, in memory only; nothing keyless is
  written to `.local/demo.sqlite`. A failure is never cached as if it were an answer.
* **Ceilings, fail closed.** 60 requests in a rolling 60-second window and 600 for the process run. Past either, the
  route answers `keyless_budget_exhausted` and makes no request. The run ceiling is not released by the passage of
  time; only a restart resets it, and that is stated rather than hidden.
* **Four honest failures**, never a silent fixture: `keyless_unavailable` (the subset does not publish that endpoint,
  with the reason naming what a key would be needed for), `keyless_budget_exhausted`, `keyless_rate_limited` (the
  shared pool refused us — the observed case), and `keyless_provider_unavailable` (non-OK status, provider error code,
  unparseable body, oversized body, or a transport failure). Each carries the provider's own message where there is
  one, trimmed to 300 characters.
* **Bounded like the keyed path.** Keyless parameters go through the same `cmcParams` canonicaliser, the same
  100-row and 20-identifier ceilings, the same refusal of symbolic asset identity, and — for k-line, which is not in
  the shared catalog — an equivalent local validator: verified platform aliases only, a real contract address, one
  named candle width, a USD unit and a bounded page.
* **Not reachable from the parent product.** The packaging regression walks `src`, `supabase/functions`, `worker`,
  `netlify`, `scripts`, `local-intelligence-worker`, `image-worker`, `render-worker` and `shared` and fails if any
  source file contains the keyless base or the `coinmarketcap_keyless` label.

**Conclusions, none of which loosen anything.**

* The pool grants a small burst per IP and then refuses. A capture must pace itself and must treat a refusal as a
  result to record, not an error to retry away. `scripts/capture-keyless-evidence.mjs` does exactly that: bounded
  attempts, generous spacing, and a refusal written with its verbatim `status`.
* `credit_count` is reported as 1 on a surface that presents no key and debits no account. It is recorded verbatim
  and is deliberately not the same field as the artefact's `creditsSpent`, which is 0.
* `error_code` is the **string** `"0"` on success here, which is why success is tested as `Number(code) !== 0`.
* `/v1/fiat/map` answers 403/1005: the keyless subset does not publish it. It is not mapped and stays unmapped.
* `/v1/dex/tokens/transactions`, `/v1/cryptocurrency/map` and `/v1/cryptocurrency/listings/latest` answered keyless
  but are **not** in `KEYLESS_ENDPOINTS` and were not added. A route is mapped when a demo journey needs it, not
  because a probe succeeded.
